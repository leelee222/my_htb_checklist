Certified Junior Cybersecurity Analyst — Mission Briefing

Grey-box pentest of 5 machines + ~27 SIEM alert triages. You need ≥ 80 points to pass. Each flag = 10 pts. The report is graded — a failing report fails you even at 100 pts technical.

Before You Start — Setup
Do this the day before. Never on exam day morning.
Prep ▼
1
Phase 1 — Mass Recon (All 5 Hosts)
Run everything in parallel. Don't touch exploits yet — build the full map first.
H 0–4 ▼
Fire all nmap scans simultaneously. While they run, add IPs to /etc/hosts and start browsing HTTP ports manually.
2
Phase 2 — Linux Exploitation
Attack order: WEB01 first (most exploitable), then NIX01, then NIX02. Reuse every cred you find.
H 4–20 · 60 pts ▼
🐧 Linux WEB01 Web Server — Start here
🐧 Linux NIX01 Dev Server
🐧 Linux NIX02 Email Server
3
Phase 3 — Windows Exploitation
Linux creds often reuse on Windows. Try everything before bruteforcing.
H 20–30 · 40 pts ▼
🪟 Win WIN01 Windows Client
🪟 Win WIN02 Management Server
4
Phase 4 — SIEM Alert Triage
~40 alerts presented, ~27 required. TP/FP with evidence. Budget ~6 hours.
H 30–36 · ~20 pts ▼
🔴 True Positive Indicators
Known attack tools (mimikatz, meterpreter, cobalt strike)
Encoded/obfuscated PowerShell (-enc, -e, base64 blob)
Unusual parent→child (winword.exe → cmd.exe)
Mass authentication failures in short window
Process injection (explorer → malicious child)
Lateral movement (psexec, wmiexec, evil-winrm IOCs)
LOLBAS abuse (certutil download, regsvr32 COM)
Beaconing: repeated outbound to same unusual IP
Privilege escalation events (4672, new admin group add)
✅ False Positive Indicators
Legitimate admin tools (psexec by IT team, scheduled tasks)
Known business IPs / internal subnets
Vulnerability scanner traffic (expected in environment)
Software update processes (Windows Update, antivirus)
Normal business hours + expected user + expected host
Developer tools on developer machines (pyinstaller, gcc)
Auth failures from known service accounts
5
Phase 5 — Report Writing
This is where most people lose points. Be specific. Be professional. Be complete.
H 36–48 · Graded ▼
A weak report can fail you even with 100 pts in technical flags. Graders read every word.
Executive SummaryNon-technical language. State the overall risk, how many machines were compromised, what an attacker could do with this access. One page maximum.
Attack NarrativeTell the story. WEB01 gave foothold → found credentials → reused on WIN01 → dumped hashes → WIN02 compromised. Show the chain, not just individual bugs.
Per-Finding FormatTitle → Severity (Critical/High/Medium/Low) → CVSS v3.1 Score → Affected Host → Description → Root Cause → Impact → Proof (screenshot + command) → Remediation
ScreenshotsEvery flag: cat user.txt with hostname visible. Every exploit: command + output. Every critical step. Timestamp must be visible.
SIEM TableAlert ID | TP/FP | MITRE TTP | Evidence | Classification Reasoning — one row per alert, all ~27 completed.
RemediationBe specific. "Patch to version X.Y.Z", "Disable anonymous SMTP relay", "Enforce MFA on RDP". Never just "apply patches".
⚡ Golden Rules
Credential reuse is kingEvery time you find a password — spray it across SSH, SMB, WinRM, RDP, web apps on all other machines immediately. Most CJCA pivots work this way.
Screenshot before you move onOnce you close that shell you may never get it back. Flag + hostname + timestamp, every single time.
3-hour ruleStuck on a machine for 3 hours straight? Stop. Move to the next one. Return with fresh eyes. 80 pts is the goal, not 100.
Write the report in real-timeDon't wait until the end. Log findings in SysReptor as you go. The last 12 hours should be polish, not panic.
The report can fail youTechnical points only count if your report is accepted. A machine pwned with no evidence, no CVSS, and no remediation is zero points.
